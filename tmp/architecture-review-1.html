Codebase Architecture Review

Surfacing architectural friction and deepening opportunities.

1. Extricate Spatial Layout from Semantic Renderers

Strong

Files

components/views/CalendarView.tsx components/YearGrid.tsx

Problem

The view modules (e.g., CalendarView) are highly shallow. Their interface is essentially taking the massive AppConfig object and calculating vast amounts of styling internally. They intertwine the spatial layout logic (conditional tracking for rows vs. columns vs. chunks, grouping by seasons) directly with the cell rendering rules (granularity switching, date identification). Deletion test: deleting CalendarView doesn't concentrate complexity; it scatters 25 inline layout checks straight back up to the caller.

Solution

Create a proper seam separating the LayoutStrategy (which purely handles row/column wrappings, grouping, and chunking) from the ChronologyRenderer (which purely iterates over logical time and paints Cell components). The parent YearGrid will bridge them, providing multiple discrete adapters (e.g. ChunkedLayout, SeasonGridLayout) fulfilling the unified interface.

Benefits

High locality for layout logic. Instead of scattered width = mode === 'rows' ? x : y conditions across 400 lines, layout behavior lives cohesively inside a single strategy adapter. Adding new layouts offers deep leverage because you only need to write a tiny grid coordinator vs duplicating month iteration hooks. You can unit test seasonal block grouping purely mathematically.

2. Shatter AppConfig into Domain Contexts

Worth exploring

Files

types.ts hooks/useGridData.ts

Problem

AppConfig acts as a God struct harboring nearly 50 completely unrelated properties (from visual border radii to life expectancy computations). Because it has no domain boundaries, dependencies seep universally. For example, useGridData—which should purely compute chronological modules—breaks boundaries entirely by parsing explicit layout overrides and CSS colors. The interface passes sheer mass rather than strict behavioral rules.

Solution

Shatter the monolith to create discrete domain interfaces (e.g., ChronologyModel, VisualThemeModel, GridDimensionsModel). Remove all awareness of visual properties (like colors) out of useGridData, leaving it as a pure date calculator that yields isolated data. Introduce a specialized ThemeAdapter on the UI level that applies colors contextually mapped from the chronology dates.

Benefits

Rebuilding these models creates massive locality—style changes don't force chronological logic updates. A caller gains enormous leverage when invoking the timeline domain, gaining pristine blocks of logical time without dragging along visual payload sizes and HTML string parsing. The chronological engine instantly becomes 100% unit-testable directly.

3. Interactive Intent Seam (Sidebar Decoupling)

Speculative

Files

components/sidebar/SetupTab.tsx

Problem

The sidebar interface dictates complex cascading rule changes inline inside individual component .onClick() arrays. State overrides (e.g. "when hitting 'Group by Season', immediately set 'monthsPerRow' to 3 and 'startFromJan' to true") live inside raw buttons. There is no state management boundary or adapter. Consequently, logic is totally distributed and deeply brittle.

Solution

Interpose an IntentEngine seam (using a localized state wrapper/reducer system with explicitly defined verbs like "PRESET_12_WEEK_APPLIED"). Instead of directly manipulating 8 loose fields, React dispatches a unified semantic instruction across the interface.

Benefits

Concentrates heavy configuration inter-dependency logic strictly into one isolated, predictable spot (High locality). Tests can purely dispatch commands without ever needing to emulate rendering sidebars.

Top Recommendation

Candidate 1 (Extricate Spatial Layout from Semantic Renderers) is the clearest win. Currently, any attempt to adapt layout algorithms requires heavily polluting pure view loops with nested logic expressions. Splitting it gives profound leverage to compose a multitude of custom calendars out of unified grids, fundamentally changing how fast layouts can scale up moving forward.
